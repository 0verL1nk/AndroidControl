# 真机复验清单（0.3.0）

> 节点侧与自动化测试已经覆盖了协议与字节路径；这份清单只列**必须用真手机**确认的三件事。
> 每项都给出"怎么点"和"看到什么算通过"，跑完把结果补进 `docs/ROADMAP.md` 的验收表。

前提：

- 手机已装 0.3.0（或 `:app:assembleDebug` 的 debug 包）；
- 长辈端已按 `docs/ops/elder-device-setup.md` 完成 Shizuku 与权限；
- 中继按 `docs/ops/relay-node.md` 部署，TLS 端口与证书指纹已知。

---

## 1. TLS 配对（任务 3.4）

**配置**（二选一）

```bash
# A. adb 直接写配置（两台手机都要做：一台长辈、一台控制）
adb shell am start -n dev.ling.app/.HomeActivity \
  --es relay_host <节点地址> --ei relay_port 27443 \
  --es relay_fingerprint "<SHA-256，冒号可有可无>"
```

B. 界面上填：

- 长辈端：首页标题进入详情页 → 高级信息 → 设置中继节点 → 填 `host:port` 与指纹 → 保存并重连；
- 控制端：连接页右上角设置 → 中继节点 + 中继证书指纹。

**通过标准**

1. 控制端输入长辈首页的 6 位数字 → 3 秒内出画面、能点击；
2. 节点日志没有 `TLS 握手失败`；`journalctl -u ac-relay -n 20 | grep 配对成功` 有记录；
3. **负向**：把指纹故意改错一位 → 连接必须失败，长辈端/控制端日志出现
   `证书指纹不匹配`（不会把口令发出去）；
4. 公网扫描：明文端口（27180）从外部不可达，只有 27443 可连。

> 若用网页控制端：它走 `wss://`（Cloudflare/Caddy），与指纹无关，本条不需要它参与。

## 2. 文本输入（任务 5.2）

1. 长辈端打开一个可输入的界面（设置里的搜索框、或浏览器地址栏），**先点一下输入框**；
2. 控制端顶栏键盘图标 → 输入 `hello123` → 发送；
3. 通过标准：文字出现在输入框里；网页端（底部输入条）同样成功；
4. 已知限制：中文等字符是否成功取决于目标应用与设备键盘映射（`INJECT_TEXT` 的引擎限制），
   失败不算回归，但请在 issue 里记录机型与应用。

---

## 3. 网页双向语音（任务 6.3）

1. 网页控制端连上后，点顶栏「语音」，浏览器询问麦克风时选允许；
2. 双方各说一句话；
3. 通过标准：
   - 双向都能听清，延迟与系统电话接近；
   - 长辈端没有回声（AEC 生效；若出现回声，先在长辈端确认用的是扬声器而非耳机）；
   - 点「停止语音」后画面与控制仍正常，语音可以再次开启；
   - 拒绝麦克风权限时出现「需要麦克风权限才能语音」而不是白屏或崩溃。
