# 路线图：远程接管 Android 手机

**最后更新**：2026-10-20
**当前阶段**：M1 收尾（跨公网闭环已实测通过），M2 进行中

> 2026-10-20 进展：中继改为 Rust 单二进制（协议 v2 不变，配对 0.5–0.7s）；
> 控制通道与视频流解耦，控制断线独立自愈（不再连带画面重连）；
> 引擎默认分辨率提到 1280 长边、码率上限 4 Mbps（原 720p/2 Mbps 偏糊）。

## 一句话

让子女在外网直接操作长辈的手机。自用、不 root、长辈端零操作。

## 已经确定的形态

```
┌── 长辈手机（家里 Wi-Fi，长期插电）────────────────┐
│  极简 App（求助 / 正在被协助 / 结束）              │
│    └─ 经 Shizuku 以 shell 身份启动采集引擎         │
│    └─ 在隧道接口上暴露 控制流(27185) + 视频流(27186) │
└───────────────────▲──────────────────────────────┘
                    │ WireGuard 隧道 10.66.66.0/24
        ┌───────────┴───────────┐
        │  自建节点（新加坡）      │  wg0 = 10.66.66.1
        │  加密 + 中继            │  实测到国内 32ms
        └───────────▲───────────┘
                    │
┌───────────────────┴──────────────────────────────┐
│  控制端手机（你的手机，任意网络）                    │
│  fork ScrcpyForAndroid：解码 / 渲染 / 触摸 / 输入法  │
│  只把「连 ADB」换成「连长辈端」                      │
└──────────────────────────────────────────────────┘
```

**核心原则**：不重造引擎。采集/编码/注入用 scrcpy-server，控制端 UI 与解码用上游，
自研只做"长辈端"和"连接层"。

## 里程碑

### M0 — 立项调研与可行性 ✅ 已完成（2026-10-18）

- 调研市面产品、开源项目、技术路线、合规约束
- 在真机（Redmi K60 Ultra / Android 16）上验证：`screencap` 950ms 不可用；
  `screenrecord` 秒级延迟；**scrcpy 5.0.1 server 以 shell 身份跑通**（决定性结论）
- 识别出控制端可直接 fork 的上游项目（ScrcpyForAndroid，Apache-2.0）
- 盘点现有服务器，选定新加坡节点并建成 WireGuard 隧道（实测 32ms 到国内、766Mbps）

**产出**：`specs/001-*/research.md`、`docs/DECISIONS.md`

### M1 — 跨公网闭环 🔨 进行中

**目标**：在外网看到并操作长辈手机；长辈端零操作；**陌生人能自己搭一套**。

- US1：控制端（蜂窝网络）看到并操作长辈端
- US2：长辈手机重启后无需任何人操作即可被连接
- 开源：README + 节点脚本 + 部署手册齐备，仓库无个人信息

**退出条件**：quickstart 全部通过；SC-001~SC-005、SC-009、SC-010 达标

**最大风险**：Shizuku 能否以 shell 身份拉起 engine（tasks.md T009，第一周验证）

### M2 — 弱网与长期稳定

- 断网/切换网络自动恢复（SC-006）
- 30 分钟稳定性（SC-007）
- 长辈端被系统清理后的自愈

### M3 — 传输优化与安全加固

- 评估打洞（headscale/DERP 或 WebRTC），减少节点带宽占用与延迟
- 若国内节点延迟明显更优，切换或双节点
- 密钥轮换、审计日志、异常连接告警

### M4 — 适老体验

- 长辈端"一键求助"（主动呼叫子女）
- 敏感页面（支付/验证码）自动提示或暂停
- 语音引导 / AR 指路等低侵入替代交互
- 长辈端大字模式、方言语音提示

### M5 — 可选扩展

- iOS / 浏览器控制端
- 音频与语音对讲
- 多设备管理（多位长辈）
