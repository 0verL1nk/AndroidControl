# 路线图：远程接管 Android 手机

**最后更新**：2026-10-20
**当前阶段**：M0–M5 完成（iOS 由网页控制端覆盖，不单独开发原生 App）

> 2026-10-20 进展：Rust 中继（`audio` 角色、求助记录、WebSocket）；控制通道独立自愈；
> 敏感页面红色提示；一键求助；双向语音；息屏自动点亮/唤醒；状态语音播报；
> 引擎默认 1280 长边 / 4 Mbps；**两个 App 合并为一个**（首页显示自己的口令、
> 打开即待命，也能输入对方口令去协助）；新增 Next.js 网页控制端（WebCodecs）。

## 一句话

让子女在外网直接操作长辈的手机。自用、不 root、长辈端零操作。

## 已经确定的形态

```
┌── 长辈手机（家里 Wi-Fi，长期插电）────────────────┐
│  极简 App（求助 / 正在被协助 / 结束）              │
│    └─ 经 Shizuku 以 shell 身份启动采集引擎         │
│    └─ 在隧道接口上暴露 控制流(27185) + 视频流(27186) │
└───────────────────▲──────────────────────────────┘
                    │ WireGuard 隧道 10.66.66.0/24
        ┌───────────┴───────────┐
        │  自建节点（新加坡）      │  wg0 = 10.66.66.1
        │  加密 + 中继            │  实测到国内 32ms
        └───────────▲───────────┘
                    │
┌───────────────────┴──────────────────────────────┐
│  控制端手机（你的手机，任意网络）                    │
│  fork ScrcpyForAndroid：解码 / 渲染 / 触摸 / 输入法  │
│  只把「连 ADB」换成「连长辈端」                      │
└──────────────────────────────────────────────────┘
```

**核心原则**：不重造引擎。采集/编码/注入用 scrcpy-server，控制端 UI 与解码用上游，
自研只做"长辈端"和"连接层"。

## 里程碑

### M0 — 立项调研与可行性 ✅ 已完成（2026-10-18）

- 调研市面产品、开源项目、技术路线、合规约束
- 在真机（Redmi K60 Ultra / Android 16）上验证：`screencap` 950ms 不可用；
  `screenrecord` 秒级延迟；**scrcpy 5.0.1 server 以 shell 身份跑通**（决定性结论）
- 识别出控制端可直接 fork 的上游项目（ScrcpyForAndroid，Apache-2.0）
- 盘点现有服务器，选定新加坡节点并建成 WireGuard 隧道（实测 32ms 到国内、766Mbps）

**产出**：`specs/001-*/research.md`、`docs/DECISIONS.md`

### M1 — 跨公网闭环 ✅ 已完成（2026-10-19）

- US1 ✅ 控制端（蜂窝网络）看到并操作长辈端（实测 30fps，点击/按键生效）
- US2 ⚠️ 部分：应用存活时"长辈端零操作"成立；**重启后 Shizuku 不能自启**，
  受 HyperOS 限制（`research.md` R14），目前需要家人点两下恢复
- 开源 ✅ README / 部署脚本 / 手册 / 个人信息检查 / CI

### M2 — 弱网与长期稳定 ✅ 已完成（2026-10-20）

- 断网/切换网络自动恢复：控制端 60 次重试（约 30s 窗口）；控制流与视频流解耦，
  控制断线只重建自己（ADR-016）
- 长辈端被系统清理后的自愈：前台服务（屏幕提示 + 麦克风类型）、开机自启、引擎残留清理
- 息屏：连接时自动点亮（`power_on`）、`stay_awake`、控制端可随时"点亮屏幕"
- 画质档位：流畅（720p / 2 Mbps）与清晰（1280p / 4 Mbps 上限），弱网/丢包时
  每帧字节更少、重传更少，操作更跟手；长辈端"高级信息"里切换
- 30 分钟长跑：✅ 通过（视频 28–34 fps，语音持续，中继 0 次断开）

### M3 — 传输优化与安全加固 ✅ 基本完成（2026-10-20）

- 中继 v2 + Rust 实现，配对 0.5–0.7s；公网实测 30fps / 2Mbps
- 配对码轮换：长辈端"高级信息"里重新生成，旧码立即失效
- 审计：中继记录每对连接与断开方向；长辈端被连接时有通知 + 屏幕提示
- 打洞（WebRTC / headscale）：未做，留作可选优化

### M4 — 适老体验 ✅ 已完成（2026-10-20）

- 一键求助：长辈按"开启协助"即向中继登记求助，控制端打开 App 就能在设备卡片上看到
  "长辈刚刚按了求助"（30 分钟内有效，不需要长辈端在线）
- 敏感页面：检测到支付/银行类 App 时，长辈端屏幕变成**红色荧光 + 应用名**，
  孩子通过画面也能看到
- 语音引导：长辈端在"家人已连接/已断开"时中文播报（需要系统中文语音包）
- 大字模式：主界面 38sp 标题、64dp 主按钮

### M5 — 可选扩展

- 双向语音 ✅ 已完成（2026-10-20）：中继新增 `audio` 角色，16kHz 单声道 PCM 双向；
  两端共用 `:audio` 模块，带回声消除与后台录音（麦克风前台服务类型）
- 多设备管理 ✅ 已完成：可保存多台设备，按名字/口令区分
- 浏览器控制端 ✅（2026-10-20）：`web/` Next.js + WebCodecs，部署到 Vercel；
  中继新增 `/ws`，经 Cloudflare WSS 实测可看画面、能点击
- iOS / 平板：直接使用网页控制端（Safari 16.4+ 支持 WebCodecs 的 H.264 解码），
  不单独开发原生 iOS App——这是产品决策，不是未完成项

## 已知限制

- 重启后 Shizuku 不自启（HyperOS，平台限制，非本项目可解）：首页会显示
  「本机未启用 Shizuku」，提供一键「打开 Shizuku」入口，进去点「启动」即可恢复
- 应用已合并为 `dev.ling.app`：从旧的 `dev.ling.agent`/`dev.ling.controller` 升级时，
  需要重新授权 Shizuku 与一次性权限（配对码会重新生成一次）
- 网页控制端需要 WSS 入口：临时 Cloudflare 隧道地址每次重启会变，长期使用请建命名隧道
  或给自己的域名配 TLS 反代
- 中继是明文转发：公网暴露时请自行加 TLS（见 `docs/ops/relay-node.md`）
- 中继的求助记录只在内存里：中继重启后提示会消失
- 语音是未加密的 PCM，与中继同一信任边界；涉及敏感内容请改用系统电话
