## ADR-013：仓库不留任何个人与环境信息

**日期**：2026-10-18
**状态**：已采纳

**决策**：仓库中不得出现作者本人或任何使用者的可识别信息：公网/内网 IP、主机名、
SSH 密钥标识与指纹、账号名、邮箱、设备序列号、隧道密钥。文档一律使用
`<NODE_PUBLIC_IP>`、`<DEVICE_LAN_IP>` 这类占位符。

**理由**：项目开源后仓库是公开的；节点 IP 暴露等于把攻击面与"这台机器是谁的"一并公开。
密钥一旦进仓库，历史里就再也删不干净。

**执行方式**：
- `.gitignore` 忽略 `.secrets/`（存放本地实例信息、密钥、二维码）。
- `tools/check-personal-data.sh` 在提交前扫描：公网 IP、内网 IP、私钥块、
  已知的设备名/账号名。已接入 git pre-commit hook。
- 已对工作区与历史做了一次清洗（含一条历史提交）。

**影响**：任何人 clone 后都需要自己生成占位符对应的真实值，见
`docs/ops/node-wireguard.md` 与 `tools/setup-node.sh`。

## ADR-012：以 Apache-2.0 开源，目标是"别人能自己搭一套"

**日期**：2026-10-18
**状态**：已采纳（取代 ADR-001 的"仅自用"）

**决策**：项目开源，许可证 Apache-2.0。任何人可自行搭建节点、部署长辈端、编译两端 App。

**理由**：
- 依赖的上游都是 Apache-2.0（scrcpy、scrcpy-server、ScrcpyForAndroid），
  Apache-2.0 与它们兼容且含专利授权条款。
- 这类工具的价值在于"自己掌控自己的数据"；只有能自托管，才谈得上隐私。

**配套要求**（列入验收）：
- 节点一键脚本 `tools/setup-node.sh`，任意 Debian/Ubuntu VPS 可用。
- 长辈端部署手册面向非开发者可执行。
- 所有配置项不得硬编码个人基础设施；端点、端口、密钥由配置或脚本生成。
- **无遥测、无统计上报、无第三方分析 SDK**。
- 保留上游署名（见 `NOTICE`），fork 部分保留原许可证与版权声明。

**放弃的备选**：AGPL（对自用场景无实际收益，且与上游许可组合更复杂）；GPL（同上）。

**影响**：ADR-001 中"不上架、不分发"的结论作废；但"不走应用商店"仍然保留——
分发方式为源码 + 自编译 APK。

## ADR-011：跨公网用 WireGuard hub，暂不做打洞

**日期**：2026-10-18
**状态**：已采纳

**决策**：M1 用 WireGuard 组网，节点做 hub，两端各拿固定隧道 IP。

**理由**：
- 30 分钟可落地，加密由网络层解决，应用层不用碰 TLS。
- 实测新加坡节点到国内 32ms、出口 766Mbps，带宽与延迟都可接受。
- 两端配置分流（`AllowedIPs = 10.66.66.0/24`），不影响长辈手机正常上网。

**放弃的备选**：headscale + DERP（更复杂，M3 再评估）；自研反向隧道（要写中继服务）；
WebRTC（会重新引入 MediaProjection 依赖）。

## ADR-010：控制端 fork ScrcpyForAndroid，而不是自研

**日期**：2026-10-18
**状态**：已采纳

**决策**：`controller/` 目录 fork `Miuzarte/ScrcpyForAndroid`，只替换连接层。

**理由**：
- Apache-2.0，可自由修改与分发。
- 它的传输层（`nativecore/DirectAdbClient` 等）与解码渲染层（`MediaCodecVideoDecoder`、
  `PersistentVideoRenderer`）是分开的，替换面清晰。
- 它把 scrcpy 的 C 客户端编进 App（NDK + `NativeCoreFacade`），协议正确性由上游保证。
- 已实现中文输入、剪贴板、旋转、录制等我们本来要花大力气做的功能。

**放弃的备选**：自研 Kotlin 客户端（工作量最大、协议细节最容易出错）。

**影响**：引入较大的第三方代码量，需要维护 fork 关系，只改 `nativecore/AgentClient`。

## ADR-009：长辈端自研极简 App + Shizuku

**日期**：2026-10-18
**状态**：已采纳

**决策**：长辈端装一个自研 App，经 Shizuku 以 shell 身份启动 scrcpy-server，暴露两条
流；不顺带依赖无线调试常开。

**理由**：
- 上游方案要求"无线调试常开"，重启后可能被系统关闭，老人无法自行恢复。
- Shizuku 在 Android 13+ 可借"可信 WLAN"自启，是唯一能做到"老人零操作"的路径。
- 不 root。

**放弃的备选**：无线调试常开（安全面大、易失效）；开机自动开 adb 脚本（等同长期暴露
adbd）；root（刷机风险）。

**风险**：Shizuku 自启在部分 ROM 上不可靠 —— 列为 M1 第一优先验证项。

## ADR-008：确认服务器归属，接受新主机密钥

**日期**：2026-10-18
**状态**：已采纳

**决策**：接受 `<NODE_PUBLIC_IP>` 的新 ED25519 主机密钥
（`SHA256:8GT9JH/9B77lOoRdMEDoqsrTWdDpoq6X1tPMyXwUnSo`）。

**理由**：服务器 `authorized_keys` 中存在账号主人的公钥，与本地 `id_ed25519.pub`
指纹一致；服务器上的运维痕迹（安装脚本、命令历史时间戳）也指向账号主人本人。
密钥变化源于 2026-09 底的重装系统。

**确立的规则**：接受主机密钥变更前必须取得独立证据；"能连上"不等于"是同一台机器"。

## ADR-007：网络测量必须绕开本机代理

**日期**：2026-10-18
**状态**：已采纳

**决策**：本项目的所有延迟/连通性测量，必须从服务器侧、手机侧或绕开 sing-box TUN 的
环境进行；不接受在 TUN 模式下测出的 RTT。

**理由**：实测发现「ping 新加坡 <1ms、tracert 一跳」纯属本地代理伪造。

## ADR-005：复用 scrcpy-server 作为采集引擎

**日期**：2026-10-18
**状态**：已采纳

**决策**：vendor scrcpy-server 5.0.1，固定版本。

**理由**：真机实测跑通；Apache-2.0；shell 身份下不受 MediaProjection 的每次授权与
锁屏即停限制；注入事件不带无障碍标记，金融 App 无法据此识别。

**放弃的备选**：MediaProjection + 无障碍（老人每次要点"同意"，Android 16 锁屏即断）。

## ADR-004：不 root

**日期**：2026-10-18
**状态**：已采纳

**决策**：长辈端不做 root，shell 能力由 Shizuku 提供。

**理由**：刷机有变砖与保修风险；解锁 BL 会导致部分金融 App 拒跑。

## ADR-003：控制端形态为 Android App

**日期**：2026-10-18
**状态**：已采纳（用户选择）

**决策**：控制端做 Android App（手机控手机），不做网页/桌面端。

**理由**：真实使用场景是子女在外面用手机；且 WAN 场景下必须有一个常驻两端之间的可靠
连接器。iOS/浏览器控制端列为 M5 可选。

## ADR-002：场景以跨公网为前提

**日期**：2026-10-18
**状态**：已采纳

**决策**：设计以"控制端在蜂窝网络、长辈端在家用 Wi-Fi"为前提；局域网只是它的退化情况。

**理由**：用户澄清真实使用场景不在同一局域网。此决策推翻了早期"局域网自研 agent +
代理"的设计（保留在 `docs/superpowers/specs/`）。

## ADR-001：项目定位为个人自用

**日期**：2026-10-18
**状态**：**已被 ADR-012 取代**（2026-10-18 起项目改为 Apache-2.0 开源、可自托管）

**决策**：自用、不上架、不分发。

**理由**：用户明确。因此应用商店审核、ICP/APP 备案、软著等不适用；但保留安全实践
（绑定白名单、可见提示、一键结束、不落盘）。
