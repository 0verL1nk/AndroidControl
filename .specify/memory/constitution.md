# 远程接管 Android 手机 Constitution

## Core Principles

### I. 实测优先（Measure First）

任何架构决策必须由本机实测数据支撑，禁止用"网上说"或凭记忆替代验证。每条关于延迟、
权限、可行性的断言都要能指向一次探针、基准或官方文档。探针代码可以丢弃，测量结果
必须留档。

**理由**：本项目建立在"免 root 也能采集和注入"这一非显然结论上，一旦假设错误，
后续所有工作都会作废。

### II. 特权最小化、来源可替换（Least Privilege, Swappable Source）

被控端只申请完成功能所必需的最低权限；需要 shell 身份的只有"启动采集引擎"这一动作。
特权来源（开发期 PC adb / 生产期 Shizuku / 可选 root）必须隐藏在统一接口之后，
业务代码不得感知具体来源。默认不 root。

**理由**：权限来源是本项目最不稳定的一环（ROM 差异、重启失效、未来系统限制），
把它关在一个边界里，替换成本才低。

### III. 复用验证过的引擎（Reuse Proven Engines）

屏幕采集、硬件编码、输入注入复用经过验证的第三方实现（当前为 scrcpy-server 5.0.1，
Apache-2.0），以 vendor 方式固定版本并随仓库锁定。自研范围仅限：特权启动、代理转发、
传输层、控制端 App、适老体验。

**理由**：采集/注入是整条链路最容易翻车、最难调试的部分；已验证的实现能把不确定性
压到最小。

### IV. 安全默认开启（Secure by Default）

无配对码不可连接；配对成功后绑定设备白名单；被控端全程可见"正在被控"并可一键断开；
不做无鉴权的广播发现或直连；公网阶段必须加密传输；默认不落盘屏幕内容。

**理由**：这条通道能点亮被控手机上的任意应用，泄露代价不可接受，且此类工具是电诈
高发载体。

### V. 可执行验收（Executable Acceptance）

每个用户故事必须有可复现的验收方法：协议层用单元测试与官方测试向量；端到端用脚本化
点击、延迟 p50/p95、帧率、断线恢复次数。文档中的"完成"以测试或实测结果为准。

**理由**：规格会腐烂，测量不会。

### VI. 文档即路线（Docs Are the Route）

规格、计划、任务、决策记录、路线图保持同步。每次重大取舍写入决策记录；新会话仅凭
仓库文档即可恢复完整上下文。

**理由**：项目跨越多个里程碑，且由 AI 协作开发，上下文连续性依赖文档而非记忆。

### VII. 开源可自托管，隐私不出仓库（Open & Self-Hostable）

项目以 Apache-2.0 开源，任何人都应能自行搭建节点、部署长辈端、编译两端 App。
**仓库不得包含任何使用者的可识别信息**：公网/内网 IP、主机名、密钥、账号名、邮箱、
设备序列号一律使用占位符。延续上游署名。

**理由**：这类工具的价值在于"自己掌控自己的数据"；只有能自托管才谈得上隐私。而仓库
一旦公开，泄露的不仅是信息本身，还有"这台机器是谁的、在哪、在跑什么"。

**执行**：`.secrets/` 存放本地实例信息并被忽略；`tools/check-personal-data.sh` 在提交前
自动扫描；发行物中不得包含遥测、统计上报或第三方分析 SDK。

## 技术约束（Technical Constraints）

- 平台：Android 原生，Kotlin；控制端与被控端均为 Android App。
- SDK：minSdk 26，compileSdk / targetSdk 36（以本机 `E:\AndroidStudioSDK` 为准）。
- 不 root。生产期特权来源为 Shizuku；开发期允许 PC adb。
- 传输：M1 为跨公网，链路加密由 WireGuard 提供；应用层不自行实现加密，除非引入
  不经过隧道的直连路径。
- 采集引擎版本与协议严格匹配；客户端与服务端同版本发布。
- 许可证 Apache-2.0；不得引入与本许可证不兼容的第三方代码。
- **无遥测**：不接入任何统计、崩溃上报或广告 SDK。
- 文档与提交信息使用中文；代码标识符、日志键名使用英文。

## 开发流程（Development Workflow）

- 采用 Spec Kit：constitution → specify → plan → tasks → implement。
- TDD：协议层必须先写失败测试再实现；Android UI 以仪器测试和验收脚本补足。
- 小步提交：每个任务或逻辑组一个 commit，提交信息说明"为什么"。
- 每个里程碑结束更新 `docs/ROADMAP.md` 与 `quickstart.md`，并记录与计划的偏差。

## Governance

- 本宪法优先于其他开发实践；修改必须在文档中说明理由并递增版本号。
- 所有实现计划必须通过 Constitution Check 才能进入任务拆分。
- 复杂度必须被证明必要；能复用不自研，能测量不猜测。
- 版本策略：MAJOR 为原则删除/重定义，MINOR 为新增原则或实质扩展，PATCH 为措辞澄清。
