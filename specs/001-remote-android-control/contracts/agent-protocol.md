# Contract: 长辈端 ↔ 控制端 会话协议（ACP/1）

**Date**: 2026-10-18
**Transport**: TCP over WireGuard（隧道网段 10.66.66.0/24）
**Ports**: 控制通道 27185，视频通道 27186（长辈端监听）

## 1. 连接流程

```
控制端                                    长辈端
  │                                          │
  ├── TCP → 10.66.66.3:27185 ───────────────▶│  控制通道
  ├── HELLO  ───────────────────────────────▶│
  │                                          │  校验绑定白名单 + 版本
  │◀───────────────────────────── WELCOME ───┤
  │                                          │
  ├── TCP → 10.66.66.3:27186 ───────────────▶│  视频通道
  ├── AUTH <token> ─────────────────────────▶│
  │◀──────────────────────────────── OK ─────┤
  │                                          │
  │◀═════ scrcpy 视频流（原样透传）══════════┤
  ├═════ scrcpy 控制消息（原样透传）═════════▶│
```

两条 TCP 连接分工明确，避免多路复用的复杂度：**控制通道**跑握手、心跳与 scrcpy 控制
消息；**视频通道**只跑 scrcpy 视频流（大带宽、单向）。

## 2. 控制通道消息

所有消息为 UTF-8 文本行，以 `\n` 结尾（便于抓包排障；控制通道流量极小）。

| 方向 | 消息 | 说明 |
|---|---|---|
| C→E | `HELLO ACP/1 <controllerId> <pubkey-b64> <nonce-b64>` | 发起会话；nonce 为 16 字节随机数 |
| E→C | `WELCOME ACP/1 <sessionId> <token-b64> <sig-b64>` | 接受会话；token 用于视频通道；sig 为长辈端对 `nonce` 的签名 |
| E→C | `REJECT <code> <reason>` | 拒绝；code 见下表 |
| E→C | `PING <seq>` / C→E `PONG <seq>` | 心跳，每 5 秒；连续 3 次无响应判定断线 |
| E→C | `BYE <reason>` | 主动结束（长辈端点击"结束"或系统要求关闭） |

### 拒绝码

| code | 含义 |
|---|---|
| `NOT_BOUND` | 控制端不在白名单 |
| `REVOKED` | 绑定已吊销 |
| `VERSION` | 协议版本不匹配 |
| `BUSY` | 已有会话进行中（单会话限制） |
| `BAD_SIG` | 签名校验失败 |

## 3. 视频通道

- 控制端连接后**必须**先发送 `AUTH <token-b64>\n`，长辈端校验通过后回 `OK\n`，
  随后开始透传 scrcpy 视频流。
- token 与本次会话绑定，会话结束即失效。
- 校验失败直接关闭连接，不发送任何视频数据。

## 4. 透传语义

- 控制通道在 `WELCOME` 之后进入**裸透传**：控制端写什么，长辈端就写进 scrcpy 的
  control socket；反之亦然。中间不做解析。
- 视频通道在 `OK` 之后同理，透传 scrcpy 的 video socket 字节流
  （含 64 字节设备名、4 字节 codec id、12 字节包头）。
- **不做二次封装**：任何重封装都会引入延迟与出错面；scrcpy 的协议已经足够。
- scrcpy 的客户端/服务端版本必须匹配，由 `WELCOME` 中的版本号协商拦截。

## 5. 断线与恢复

- 任一条 TCP 断开 → 会话进入 `DISCONNECTED`，长辈端保留 scrcpy 引擎 15 秒
  （期间视频数据丢弃而非阻塞），控制端在此期间重连可恢复。
- 超过 15 秒 → 关闭引擎，会话 `ENDED`，控制端需重新握手。
- 长辈端"结束协助"→ 立即关闭两条 TCP 与引擎。

## 6. 安全

- 会话建立依赖 WireGuard 提供的链路加密与身份（对端隧道 IP）。
- 额外一层 `pubkey + nonce + sig` 校验，防止隧道内其他 peer 冒充。
- token 为一次性随机数，不复用。
- M1 不在应用层再做 TLS（WireGuard 已提供）；M3 若引入非隧道路径，必须补 TLS。
